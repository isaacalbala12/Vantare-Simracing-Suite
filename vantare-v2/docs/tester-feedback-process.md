# Reportar un problema o una sugerencia

Usa el canal de feedback indicado en las notas de la build que estás probando, o el formulario de reporte disponible en esa build. No asumir nombres de canales o sincronización automática a partir de un documento antiguo.

## Qué incluir

- Versión de la app y canal; versión de Windows.
- Pantalla, perfil de prueba y simulador utilizado.
- Estado de la fuente: live, desconectada o fixture explícito de un entorno de prueba.
- Pasos para repetirlo, resultado esperado y resultado observado.
- Si ocurre siempre y si cambia al reiniciar o volver a abrir el perfil.
- Captura o diagnóstico revisado por ti cuando ayude a entender el fallo.

No adjuntar credenciales ni paquetes indiscriminados de perfiles/logs. La exportación diagnóstica debe mostrar el contenido permitido antes de enviarlo; ver [contrato](telemetry-core/inspector-privacy-diagnostic-export-isa-104.md).

## Qué reportar

Cierres inesperados, cambios que no persisten tras confirmar autoguardado, errores de datos, diferencias entre Studio/Desktop/OBS y fallos de cuenta, audio o actualizador. La disponibilidad esperada depende de las notas y del alcance de la build. No descartar un problema de Engineer, Pedals o un widget porque figurase como futuro en junio.

Las sugerencias deben explicar qué intentabas hacer y qué te impide hacerlo. [Incidencias por versión](tester-known-issues.md).

## Seguimiento interno

El equipo registra el problema en Notion y enlaza la referencia GitHub necesaria para código y CI. Un reporte recibido no significa reproducido, corregido, integrado ni publicado. No se promete sincronización automática entre Discord, archivos Markdown y Notion.
